## Current Architecture

**Decision (Feb 2, 2026):** Split into 5 category files + search index

### Files Generated by `generate_summary.py`
- `docs/data/incidents-summary-citizens.json`
- `docs/data/incidents-summary-immigrants.json`
- `docs/data/incidents-summary-observers.json`
- `docs/data/incidents-summary-schools-hospitals.json`
- `docs/data/incidents-summary-response.json`
- `docs/data/search-index.md`

### How It Works

**Frontend (`app.js`):**
1. Fetches all 5 category files in parallel via `Promise.all()`
2. Deduplicates by `filePath` (dual-category incidents appear in multiple files)
3. Sorts by date descending

**Cloudflare Function (`functions/entry/[slug].js`):**
1. Fetches all 5 category files in parallel
2. Searches for incident by slug across all files
3. Returns first match for OG tag injection

**Search Index (`search-index.md`):**
- Lightweight markdown file for quick searching
- Format: `date | city | category | title`
- Used during daily incident searches to quickly check existing coverage

### Benefits
- **Parallel loading:** Browser fetches all 5 files simultaneously
- **Smaller individual files:** Citizens (most viewed) loads in ~50ms
- **Fast search:** `search-index.md` is easy to scan
- **Auto-generated:** Pre-commit hook keeps everything in sync

### Dual-Category Handling
Incidents with multiple types (e.g., `citizens, schools-hospitals`) appear in both relevant category files. The frontend deduplicates when merging.
